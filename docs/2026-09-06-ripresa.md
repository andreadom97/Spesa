## Cose da sapere che non si deducono dal codice

- Per un PDF la riga in `import_uso` viene registrata con `pagine = 0` perché contarle
  significherebbe aprirlo prima del tetto (un PDF costruito ad arte esaurisce la
  memoria già in `load`). Il check SQL è `0..12`.
- Con l'ordine "registra, poi conta", la data nel 429 è "il più vecchio import nella
  finestra più 30 giorni" e il tentativo rifiutato resta nella finestra: alla data
  indicata può arrivare un altro 429. Imprecisione accettata.
- `IMPORT_CONCORRENZA=0` vale 1, non 4. `IMPORT_LIMITE_30GG` vuota vale 3.
- L'errore tsc su `LayoutProps` in `layout.tsx` compare solo senza `.next/types`: dopo
  un `npm run build` sparisce. Non è nostro.
- `diete/` è gitignored e contiene dati sanitari veri: mai in git, mai nei report. L'eval
  gira solo in locale con quella cartella e la chiave.
- Il file `scripts/eval-import-report.ts` era binario per git (byte NUL nel sorgente)
  fino al commit di correzione; ora è testo.
- La prima chiamata di pagina dovrebbe leggere la cache scritta dall'indice: il numero
  `cache letti` nel report dell'eval è il primo da guardare. Se è zero, usare lo stesso
  schema di structured output per indice e pagine.

con task, file, interfacce e passi TDD. Esecuzione **subagent-driven**: un subagent

l'orchestratore rivede il diff, fa girare `npx vitest run && npx tsc --noEmit && npm run lint && npm run build`,
committa un task per volta con messaggio in italiano e pusha. Prima di una PR: una
review di correttezza e una di sicurezza in sola lettura, poi un subagent di
correzione con la lista consolidata. Commit con `Co-Authored-By: Claude Fable 5.1` e
`Claude-Session`. Codice, commenti, test e documenti in italiano.
